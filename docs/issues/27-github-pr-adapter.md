# Title

GitHub PR adapter (Octokit)

## Summary

Implement `git/githubPr.ts`: token/endpoint resolution, repo-slug parsing from the origin
remote, idempotent PR create-or-update, label application, and the PR body renderer.

## Context

The only GitHub-API surface in v1 (DESIGN §12.3). Kept adapter-shaped so a GitLab
implementation is additive (ADR-001/ADR-003 posture). PR bodies are outward-facing
artifacts — the no-secrets rule applies (T-SECRET).

## Scope

- In: `src/git/githubPr.ts`, `src/git/remote.ts` (owned HERE, not Issue 26: origin URL
  retrieval + owner/repo parsing), `src/report/prBody.ts`, unit tests with nock (no
  live API).
- Out: local git (Issue 26), strategy flow (Issue 28), issue/label management beyond
  adding configured labels.

## Detailed Requirements

1. Add runtime dep `@octokit/rest`. Exported client factory (the explicit test seam):
   ```ts
   createGitHubClient(opts: { env: NodeJS.ProcessEnv; version: string }): Octokit
   // token = env.GITHUB_TOKEN ?? env.GH_TOKEN (absent → EnvError naming both, exit 4;
   // the used token value is passed to registerSecretValue);
   // baseUrl = env.GITHUB_API_URL when set (GHES);
   // userAgent: "i18n-agent/<version>"; retries/throttling plugins OFF.
   ```
2. `remote.ts` (owned by this issue): `getOriginUrl(root)` via
   `execa("git", ["remote", "get-url", "origin"])` (argv array, no shell — same T-CMD
   rules as Issue 26) and `parseRepoSlug(url): { owner, repo }` supporting
   `git@github.com:o/r.git`, `ssh://git@github.com/o/r.git`,
   `https://github.com/o/r(.git)`, and GHES hosts (any host accepted). Unparseable →
   `GitError` showing the URL **with userinfo credentials stripped**
   (`https://token@host/…` → `https://***@host/…`; test with an embedded token —
   T-SECRET).
3. API:
   ```ts
   export interface PrSpec { owner: string; repo: string; head: string; base: string;
     title: string; body: string; labels: string[] }
   ensurePr(octokit: Octokit, spec: PrSpec):
     Promise<{ url: string; number: number; created: boolean }>
   ```
   Flow: `GET /repos/{o}/{r}/pulls?head={owner}:{head}&state=open` → exists: PATCH
   title/body → else POST create. Labels: `POST /issues/{n}/labels` with configured
   labels; 403/404/422 label failures → `logger.warn` + continue (never fail the run,
   DESIGN §12.3).
4. Error mapping: 401/403 token problems → `EnvError` with scope hint
   (`contents: write, pull-requests: write`); 404 repo → `GitError`; 422 create
   validation (e.g. no diff) → `GitError` carrying GitHub's message; 5xx → single retry
   after 2 s then `GitError` (PR calls are cheap; full retry machinery not reused —
   document divergence).
5. `prBody.ts` (DESIGN §15.3): renders from `RunReport` (type from Issue 13).
   Table spec: one row per locale — `RunReport.files[]` (file×locale grain) is grouped
   by `locale` and counts are summed across files; columns
   `Locale | Translated | Stale fixed | Adopted | Failed | Warnings` (warnings derived
   from warn-severity issues); rows sorted by config `targetLocales` order.
   `<details>` blocks: validation issues (max 100 rows + "…and N more", ordered as in
   the report) and orphans (same cap). Footer `Generated by i18n-agent <version> ·
   <docs link>` + `<!-- i18n-agent -->` marker.
   Secrecy rule + tests: the rendered body is passed through `redact()` (Issue 03)
   before any API call, the module imports neither `process.env` nor `util/env`
   (source-text test), and a test setting `process.env.FAKE_API_TOKEN` to a sentinel
   that ALSO appears in report content asserts the body shows `***` (registered secret
   values win over content, DESIGN §16 T-SECRET).
   Body capped at 60 000 chars (GitHub limit safety) with truncation notice.
6. nock tests: create path, update path (existing open PR), label warn-path (403),
   token precedence (GITHUB_TOKEN over GH_TOKEN), GHES baseUrl, 401 scope-hint error,
   422 message passthrough, body cap truncation, slug parsing matrix.

## Acceptance Criteria

- [ ] Idempotency proven: two `ensurePr` calls with same head → one create, one update
      (nock sequence).
- [ ] Label failures degrade to warnings without failing the run.
- [ ] Works against GHES via `GITHUB_API_URL` (nock on custom host).
- [ ] PR body assertions (all mechanical): `<!-- i18n-agent -->` marker present;
      length ≤ 60 000 with truncation notice when capped; locale table rows/order match
      a fixture report; details cap at 100 rows; redactor applied (poisoned-env test
      shows `***`); no env-reading imports (source-text test).
- [ ] Remote-URL errors never leak userinfo credentials (embedded-token test).
- [ ] Token absence → exit-4 `EnvError` naming both variables; used token registered
      with the redactor (spy).
