# Title

GitHub PR adapter (Octokit)

## Summary

Implement `git/githubPr.ts`: token/endpoint resolution, repo-slug parsing from the origin
remote, idempotent PR create-or-update, label application, and the PR body renderer.

## Context

The only GitHub-API surface in v1 (DESIGN §12.3). Kept adapter-shaped so a GitLab
implementation is additive (ADR-001/ADR-003 posture). PR bodies are outward-facing
artifacts — the no-secrets rule applies (T-SECRET).

## Scope

- In: `src/git/githubPr.ts`, `src/report/prBody.ts`, unit tests with nock (no live API).
- Out: local git (Issue 26), strategy flow (Issue 28), issue/label management beyond
  adding configured labels.

## Detailed Requirements

1. Add runtime dep `@octokit/rest`. Client: token = `GITHUB_TOKEN` ?? `GH_TOKEN` (absent
   → `EnvError` naming both, exit 4); `baseUrl` = `GITHUB_API_URL` env when set (GHES);
   `userAgent: "i18n-agent/<version>"`; Octokit retries/throttling plugins OFF
   (predictable behavior; our runs are single-digit calls).
2. `remote.ts` (from Issue 26) supplies `{ owner, repo }` parsed from `origin` URL —
   support `git@github.com:o/r.git`, `ssh://git@github.com/o/r.git`,
   `https://github.com/o/r(.git)`, and GHES hosts (any host accepted; host only needs to
   match the API endpoint's expectations — document). Unparseable → `GitError` with the
   URL shown.
3. API:
   ```ts
   export interface PrSpec { owner: string; repo: string; head: string; base: string;
     title: string; body: string; labels: string[] }
   ensurePr(octokit, spec): Promise<{ url: string; number: number; created: boolean }>
   ```
   Flow: `GET /repos/{o}/{r}/pulls?head={owner}:{head}&state=open` → exists: PATCH
   title/body → else POST create. Labels: `POST /issues/{n}/labels` with configured
   labels; 403/404/422 label failures → `logger.warn` + continue (never fail the run,
   DESIGN §12.3).
4. Error mapping: 401/403 token problems → `EnvError` with scope hint
   (`contents: write, pull-requests: write`); 404 repo → `GitError`; 422 create
   validation (e.g. no diff) → `GitError` carrying GitHub's message; 5xx → single retry
   after 2 s then `GitError` (PR calls are cheap; full retry machinery not reused —
   document divergence).
5. `prBody.ts` (DESIGN §15.3): renders from `RunReport` — header sentence, metadata
   list (provider/model, counts, token usage when present), per-locale markdown table,
   `<details>` for validation warnings (capped at 100 rows + "…and N more") and orphans,
   footer `Generated by i18n-agent <version> · <docs link>` + `<!-- i18n-agent -->`
   marker. Hard rule + test: output contains no env values (render with a poisoned
   report containing a fake key string in a value → appears verbatim ONLY if it came
   from translation content; assert the renderer never reads env).
   Body capped at 60 000 chars (GitHub limit safety) with truncation notice.
6. nock tests: create path, update path (existing open PR), label warn-path (403),
   token precedence (GITHUB_TOKEN over GH_TOKEN), GHES baseUrl, 401 scope-hint error,
   422 message passthrough, body cap truncation, slug parsing matrix.

## Acceptance Criteria

- [ ] Idempotency proven: two `ensurePr` calls with same head → one create, one update
      (nock sequence).
- [ ] Label failures degrade to warnings without failing the run.
- [ ] Works against GHES via `GITHUB_API_URL` (nock on custom host).
- [ ] PR body renderer output snapshot-reviewed; caps and marker present; no env reads
      (static check: module imports no env util).
- [ ] Token absence → exit-4 `EnvError` naming both variables.
